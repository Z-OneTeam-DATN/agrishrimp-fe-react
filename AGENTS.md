# Repository Guidelines

## Project Structure & Module Organization
- `app/` hosts the Next.js App Router; `app/auth` and `app/chat` are the main flows, `app/api` contains route handlers, and `app/services` plus `app/types` collect shared clients and contracts.
- `components/` houses reusable UI; keep primitives in `components/ui` and group feature composites with their route.
- `lib/` stores shared utilities (`axios.ts`, `schemas.ts`, date helpers); `hooks/` and `stores/` expose custom React hooks and Zustand state.
- Skip editing `dist/`; it is regenerated by `npm run build`.

## Build, Test, and Development Commands
- `npm run dev` — start the local Next.js dev server with hot reload.
- `npm run build` — create an optimized production bundle in `dist/`.
- `npm run start` — serve the production build locally; run after `npm run build`.
- `npm run lint` — execute ESLint across the project; blocks CI if violations exist.
- `npm run prettier` / `npm run prettier:fix` — check or auto-format according to Prettier 3 rules.

## Coding Style & Naming Conventions
- Prefer `.tsx` for components and keep strict typing on utilities in `lib/`.
- Run ESLint (`eslint.config.js`) and Prettier before pushing; both expect 2-space indentation and trailing commas.
- Use PascalCase for components, `use`-prefixed hooks, and camelCase for helpers; reserve snake_case for API payloads.
- Co-locate Tailwind styles with components; extend shared tokens through `tailwind.config.ts`.

## Testing Guidelines
- No automated test harness exists yet; colocate `.test.ts(x)` files beside the module and document the command you used (e.g., `vitest run --coverage`) in the PR.
- Mock network calls through `lib/axios.ts` and rely on data-testid attributes for DOM queries to keep assertions stable.

## Commit & Pull Request Guidelines
- Follow the conventional commits style in history (`feat:`, `refactor:`, `feat(chat):`), adding a scope when touching a specific area.
- Each PR should outline the problem, list key changes, show test evidence, link tickets, and include UI screenshots when relevant.
- Rebase on the latest `main`, confirm `npm run lint` and formatting pass, and request review from the owning feature team before merging.
